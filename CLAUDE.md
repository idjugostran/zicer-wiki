# Zicer wiki — как здесь работать

Вики по педагогике Димы Зицера: расшифровки выпусков «Любить нельзя воспитывать» →
страницы источников, концептов и сущностей. Правила формата — в `SCHEMA.md`,
`config/link-style.md`, `config/youtube-transcript.md`. Здесь только то, чего в них нет.

## Режим работы

Обработка идёт **автономно**: шаг 3 скилла `wiki-ingest` (показать takeaways и ждать
ответа) пропускается, если пользователь просит обработать видео пачкой. Останавливаться
и спрашивать нужно только на блокирующем противоречии (см. SCHEMA, Contradiction Check).

Обычная единица работы — **батч из 10 видео**, последовательно, по одному коммиту на
видео. Следующие необработанные ID:

```bash
{ grep -rhoE 'youtu(be\.com/watch\?v=|\.be/)[A-Za-z0-9_-]{11}' wiki/pages | sed -E 's/.*(v=|be\/)//'
  awk '{print $1}' config/skip.txt; } | sort -u > /tmp/zdone
grep -vxF -f /tmp/zdone config/queue.txt | head -10
```

Скачивать все десять можно параллельно (`yt-dlp … &` + `wait`), дальше — строго по
одному видео за раз: прочитать расшифровку целиком, написать страницы, проставить
обратные ссылки, прогнать гейты, закоммитить.

## Порог на создание концепта

Прежде чем заводить новую Concept-страницу — посмотреть `ls wiki/pages` и прочитать
соседние. Переиспользовать существующий концепт всегда предпочтительнее: страница
оправдана, только если приём или тезис не сводится к уже описанному. Выпуск, не давший
ни одного нового концепта, — нормальный и хороший результат, а не пробел; так и
сообщать в отчёте. Ориентир: 1–3 новых концепта на выпуск.

Если новый концепт ограничивает уже существующий (например, снимает правило в частном
случае) — это не противоречие, а граница. Прописывать её явно на обеих страницах.

## Обратные ссылки

Пользоваться `bin/patch-backlinks.py`, а не правкой руками: он сам выбирает секцию
(`## Appearances in Sources` / `## Related Concepts` у концептов, `## Relation to Other
Wiki Pages` у источников) и обновляет `sources:` и `updated:`.

## Гейты перед коммитом

```bash
python3 bin/generate-index.py
python3 bin/lint-mechanical.py          # findings должны быть пустыми
python3 bin/check-contradictions.py     # выход 0
python3 bin/audit-quotes.py <slug>      # дословность цитат, см. SCHEMA
git add -A && git diff --cached --check -- wiki config USAGE.md
```

`git diff --check` обязательно со скоупом `-- wiki config USAGE.md`: файлы `raw/*.vtt`
скачиваются как есть и завалят проверку тысячами хвостовых пробелов.

Периодически: `python3 -m unittest tests/test_lint_mechanical.py`.

После свежего клона: `git config core.hooksPath bin/hooks`.

## USAGE.md

После батча — одна строка на видео, отдельным коммитом на весь батч:

```
| 2026-09-03 | <video-id> | 14:37 | ~14 мин | 81 строк / 1792 слов (страница источника) | Opus 5 | н/д | н/д | н/д | н/д | н/д | н/д | н/д | батч12 #2/10: краткая суть. N новых концептов: [[slug]], [[slug]] |
```

Строки и слова считаются по готовой странице источника; `н/д` в незаполненных столбцах.

## Коммиты

Одно видео — один коммит:

```
docs: summarize <точное название ролика>

Wiki-Op: ingest
```

Правки корпуса без нового источника (чистка, переименования, аудит) — `Wiki-Op: lint`.
